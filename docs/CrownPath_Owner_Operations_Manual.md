# CrownPath Owner & Operations Manual
## Governance, Security, Regulatory Control, Client Operations & Platform Oversight

**Edition:** Owner / Restricted Operations

This manual is the printable operating reference for authorized CrownPath ownership and administration. It documents how CrownPath should be governed, protected, reviewed, and operated without placing passwords, API keys, MFA secrets, database credentials, payment credentials, or private provider credentials in printable material.

> **Control principle:** CrownPath Core connects curriculum, instructors, learners, clients, digital content, Avatar/Bot systems, records, security, regulatory verification, and operations. No individual automation, instructor, bot, or integration may override Owner controls, server-side authorization, lawful professional scope, or required human approval.

CrownPath follows the operating cycle:

**CORE → SIGNAL → ACTION → FEEDBACK → PROTECTION → DIAGNOSTICS → CORRECTION**

### Solar System Model
- **Sun:** CrownPath Core

- **Orbits:** APIs, events, data flows, permissions, and approved integrations

### Human Body Model
- **Brain:** Owner decision controls and approved AI assistance
- **Heart:** workflow engine
- **Nervous system:** APIs and event/command paths
- **Immune system:** cybersecurity and authorization
- **Memory:** database, audit records, regulatory vault

### Automobile Model
- **Engine:** application services
- **Battery:** infrastructure
- **Transmission:** routing/API gateway
- **Steering wheel:** Owner dashboard
- **Brakes:** security and approval gates
- **Gauges:** health, analytics, readiness
- **Sensors:** monitoring and awareness
- **Black box:** audit trail
- **Maintenance:** testing, backups, updates, recovery

Full authorized CrownPath administrative oversight, subject to system security controls and applicable law.

Teaching, lesson delivery, practical assessment, approved learner records, digital/live learning tools, and permitted content workflows. Instructor access does not equal Owner authority.

## Learner Tracks
- Home Care
- Barber
- Cosmetology / Beauty & Wellness

Learners receive only pathway-authorized learning content and their permitted records/actions.

### Permission Rules
1. Least privilege is the default.
2. Backend authorization is authoritative.
3. UI hiding is convenience, not security.
4. Object-level access must be checked for protected records.
5. Owner role cannot be casually self-assigned.

7. Role changes should be auditable.

# 7. Scope-of-Practice Controls

### Medical Boundary
CrownPath beauty, barber, scalp-camera, hair-replacement, wellness, and Home Care lessons must not be represented as authorization to diagnose or treat disease unless a separately qualified, legally authorized clinical program is created and reviewed.

### Hair Replacement Boundary
Current CrownPath curriculum is non-surgical. It excludes:
- incision;
- graft harvesting;
- graft implantation into living tissue;
- anesthesia;
- surgical transplantation;
- medical diagnosis;
- medication prescribing.

### Scalp Camera / AI Boundary
Permitted:
- standardized images;
- visible cosmetic observations;
- documentation;
- education;
- cosmetic service planning;
- referral prompting.

Not permitted:
- medical diagnosis;
- declaring disease from an image;
- exact scalp-pH claims from photographs;
- replacing qualified healthcare evaluation.

### Massage Boundary
Massage licensure varies by jurisdiction. CrownPath wellness-massage education does not itself authorize massage therapy where a separate credential is required.

# 11. Security Operations

### Authentication Controls
CrownPath uses protected authentication patterns including password hashing, authenticated sessions, MFA capability, recovery controls, login lockout/throttling, and server-side session records.

### Session Controls
- Short-lived authenticated sessions.
- Server-side session revocation for current session architecture.
- Logout revocation.
- Password-change/reset revocation of active sessions.
- Session-purpose isolation from MFA challenge tokens.

### MFA / Recovery
- MFA secrets are private and must never appear in this manual.
- Recovery codes are one-time credentials and must be protected.
- Recovery-code verification uses protected server-side hashing/HMAC controls.

# 14. Environment & Deployment Control

CrownPath separates development/demo concepts from production operations.

### Production Principles
- GitHub source control is the code source of truth.
- Automated testing should run before production confidence is declared.
- Railway is the current authoritative production hosting path.
- PostgreSQL is the production database architecture.
- SQLite may be used for development/demo/testing where appropriate.
- Production secrets belong in protected environment configuration, never public source files.
